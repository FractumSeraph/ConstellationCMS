Put your sites on your own server

Part 1 is done once per server. Part 2 is repeated for every site you add. Fill in your names and the commands below fill themselves in.

Your names

Part 1 · Set up the server (once)

The easy way: if your VPS is fresh (Ubuntu or Debian), let the studio do all of Part 1 for you: Set up a server asks for its IP address and root password and does the rest. The steps below are for doing it by hand, or on a server that already runs other things.

  1. Get a VPS

    Any small Linux server works (Ubuntu or Debian, 1 GB of memory is plenty). You need to be able to log in with SSH as root or with sudo.

  2. Point the server's address at it

    At your DNS provider, add an A record for {{ g.host_or }}{% if g.studio %} and one for {{ g.studio }}{% endif %} pointing to {{ g.ip_or }}. If you use Cloudflare, set {{ 'them' if g.studio else 'it' }} to DNS only (grey cloud) so Gemini and Gopher can reach the server.

  3. Install ConstellationCMS

    On the server:

    {% set cmd %}curl -LsSf https://astral.sh/uv/install.sh | sh uv venv /opt/constellation --python 3.12 uv pip install --python /opt/constellation constellationcms{% endset %} {% include "partials/guide_cmd.html" %}

    If the package isn't on PyPI yet, build it on your computer with uv build, copy the .whl file from dist/ to the server, and install that file instead of constellationcms.

  4. Create the server's settings

    {% set cmd %}sudo /opt/constellation/bin/constellation server install --admin-hostname {{ g.host_or }} --tls-mode {{ 'acme' if g.proxy == 'none' else 'behind-proxy' }}{% if g.proxy != 'none' %} --plain-port {{ g.port }}{% endif %}{% if g.gopher %} --gopher{% endif %}{% if g.studio %} --with-studio {{ g.studio }}{% endif %}{% endset %} {% include "partials/guide_cmd.html" %}

    It prints an installation key once. You'll paste it into this studio in a moment to connect this computer; after that, other computers connect with short pairing codes, so you don't need to keep it (a password manager is a good place if you want to).

    {% if g.studio %}

    It also prints the studio's setup link, https://{{ g.studio }}/setup?code=…. You don't need to keep it: this studio shows it again on the Servers page once you connect a site to the server.

    {% endif %}
    5. {% if g.proxy != 'none' %}

  5. Send web traffic from {{ 'Caddy' if g.proxy == 'caddy' else 'nginx' }} to ConstellationCMS

    This prints the block{% if g.proxy == 'caddy' %} for /etc/caddy/Caddyfile{% else %} for nginx{% endif %}, with every site domain you list after the command (add www.{{ g.site_or }} too if you use it). Run it first to look at it:

    {% set cmd %}sudo /opt/constellation/bin/constellation server proxy-snippet{% if g.proxy == 'caddy' %} --caddy{% endif %} {{ g.site_or }}{% endset %} {% include "partials/guide_cmd.html" %} {% if g.proxy == 'caddy' %}

    Then back up the Caddyfile, add the block to the end, check it and reload. Caddy gets the HTTPS certificates by itself:

    {% set cmd %}sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak sudo /opt/constellation/bin/constellation server proxy-snippet --caddy {{ g.site_or }} | sudo tee -a /etc/caddy/Caddyfile sudo caddy validate --config /etc/caddy/Caddyfile sudo systemctl reload caddy{% endset %} {% else %}

    Save it as a new site, enable it, add certificates (for example with certbot --nginx), then check and reload:

    {% set cmd %}sudo /opt/constellation/bin/constellation server proxy-snippet {{ g.site_or }} | sudo tee /etc/nginx/sites-available/constellation sudo ln -s /etc/nginx/sites-available/constellation /etc/nginx/sites-enabled/ sudo nginx -t sudo systemctl reload nginx{% endset %} {% endif %} {% include "partials/guide_cmd.html" %}
    6. {% endif %}

  6. Open the firewall

    Gemini uses port 1965{% if g.gopher %} and Gopher port 70{% endif %}{% if g.proxy == 'none' %}; the web needs 80 and 443{% endif %}. With ufw:

    {% set cmd %}sudo ufw allow 1965/tcp{% if g.gopher %} sudo ufw allow 70/tcp{% endif %}{% if g.proxy == 'none' %} sudo ufw allow 80/tcp sudo ufw allow 443/tcp{% endif %}{% endset %} {% include "partials/guide_cmd.html" %}

    Also open the same ports in your VPS provider's firewall, if it has one.

  7. Start it

    {% set cmd %}sudo systemctl daemon-reload sudo systemctl enable --now constellation{% if g.studio %} constellation-studio{% endif %}{% endset %} {% include "partials/guide_cmd.html" %}

    Check it from your computer. It should answer ok:

    {% set cmd %}curl https://{{ g.host_or }}/_constellation/healthz{% endset %} {% include "partials/guide_cmd.html" %}

  8. Add the server to this studio

    On the Servers page, under "Add a server", give it a name, enter https://{{ g.host_or }} as its address, and paste the installation key. This computer is then connected.

    9. {% if g.studio %}

  9. Set up the studio on the server

    Open the setup link (from the install command, or from the Servers page here after you connect a site). Choose a password, scan the QR code with an authenticator app on your phone, and type the code it shows. That's all: from then on, sign in at https://{{ g.studio }} from any browser with your password and a code from the app.

    The studio on the server keeps its own copy of your sites. To work on the same sites from this computer too, keep the two in step with Syncthing (see docs/studio-on-a-server.md).

    10. {% endif %}

Part 2 · Add a site

Each site's Domain page (in the site's menu) lists the exact DNS records to add and ticks each one when it works.

  1. Create the site here

    On the Sites page, fill in "New site" with https://{{ g.site_or }} as the web address and gemini://{{ g.site_or }} for Gemini. Gopher can be turned on later in the site's Settings, with gopher://{{ g.site_or }}.

  2. Point the domain at the server

    Add an A record for {{ g.site_or }} (and www.{{ g.site_or }} if you use it) pointing to {{ g.ip_or }}. With Cloudflare, use DNS only. If the site is live somewhere else, you can do this last: publish first, check it, then switch DNS.

    3. {% if g.proxy != 'none' %}

  3. Tell {{ 'Caddy' if g.proxy == 'caddy' else 'nginx' }} about the domain

    Open {% if g.proxy == 'caddy' %}/etc/caddy/Caddyfile{% else %}/etc/nginx/sites-available/constellation{% endif %}, add {{ g.site_or }} (and www.{{ g.site_or }}) to the names at the top of the ConstellationCMS block, then check and reload as in Part 1.

    4. {% endif %}

  4. Publish the site to the server

    On the Servers page, press Publish here next to the site. Its publish key is made the first time you publish.

  5. Publish

    Open the site's Publish page. "Preview diff" shows what will be uploaded; "Publish" sends it and makes it live.

  6. Check it

    Visit https://{{ g.site_or }}, open gemini://{{ g.site_or }} in a Gemini browser{% if g.gopher %}, and gopher://{{ g.site_or }} in a Gopher client{% endif %}. Visits show up on the site's Analytics page.

  7. Optional: Umami

    To also use an Umami dashboard, paste its tracking code into the site's Settings, under Umami analytics. The studio does the rest.

Optional · Serve the web version from GitHub Pages

GitHub Pages can serve the web pages from its worldwide network while your server keeps Gemini and Gopher. A domain name points to one place, so the web keeps {{ g.site_or }} and Gemini and Gopher get a name of their own, such as gemini.{{ g.site_or }}.

  1. Let git sign in to GitHub

    Once per computer, with the GitHub CLI:

    {% set cmd %}gh auth login gh auth setup-git{% endset %} {% include "partials/guide_cmd.html" %}

  2. Make or pick the repository

    Create a repository on GitHub (it can be empty). In its Settings → Pages, choose Deploy from a branch, the branch (usually main) and the / (root) folder. An existing Pages repository works too: the first publish replaces its files, and the old ones stay in its history.

  3. Add the target

    On the site's Publish page, add a target with platform web and target github:owner/repository. Tick Also update this target when I publish to the server so one Publish button does both. "Preview diff" shows what the first publish will change.

  4. Set the addresses

    In the site's Settings, keep the web address https://{{ g.site_or }} and set the Gemini (and Gopher) address to gemini.{{ g.site_or }}. Add gemini.{{ g.site_or }} to the server's DNS as an A record for {{ g.ip_or }}. Point {{ g.site_or }} at GitHub Pages as GitHub's custom domain instructions describe. The studio writes the CNAME file for you.

  5. What changes

    Redirects become small forwarding pages, because GitHub Pages cannot send real redirects. The server's built-in analytics no longer see web visits, since GitHub serves them. Umami still counts them, and the server still counts Gemini and Gopher.

Optional · Add a plugin

Plugins are small Python files that add shortcodes (such as {{ '{{< youtube VIDEO-ID >}}' }}), template filters and build steps. They run on this computer when a site is built, never on the server, so only use plugins you trust.

  1. Put the file in the plugins folder

    Copy the plugin (a .py file, or a folder with __init__.py) into the plugins folder next to sites in your workspace. ConstellationCMS includes an example, examples/plugins/youtube.py.

  2. Turn it on for a site

    Open the site's Settings, scroll to Plugins, tick it, fill in its settings and save. The editor's previews use it straight away.

  3. Write your own

    A plugin defines plugin = Plugin("name", "What it does") and decorates functions with @plugin.shortcode("name"), @plugin.transform, @plugin.filter("name") or @plugin.after_build. docs/plugins.md in ConstellationCMS describes each one.
